[#PossibleValueSources]
== Possible Value Sources
include::../variables.adoc[]

A QPossibleValueSource supplies allowed values and display labels for a field. Register the source in the QInstance and refer to its name from the field metadata. Sources can read another table, use a fixed enum value list, or run custom lookup code; select the type that matches the data and its access requirements.

=== QPossibleValueSource

* `name` is the unique source name; `label` is its human-readable label.
* `type` selects TABLE, ENUM or CUSTOM.
* `idType` describes the identifier field type.
* `valueFormat` and `valueFields` control how the display label is built. `valueFormatIfNotFound` and `valueFieldsIfNotFound` provide missing-value formatting.
* TABLE sources use `tableName`, with optional `overrideIdField`, `searchFields` and `orderByFields`.
* ENUM sources use `enumValues`; PossibleValueEnum implementations provide getPossibleValueId() and getPossibleValueLabel().
* CUSTOM sources use `customCodeReference`.

[source,java]
.A source using another registered table
----
QPossibleValueSource source = QPossibleValueSource.newForTable("customer");
----

Use QPossibleValueSource.newForEnum(name, enumValues) for enums. See {qqq-source-url}/qqq-backend-core/src/main/java/com/kingsrook/qqq/backend/core/model/metadata/possiblevalues/QPossibleValueSource.java[the source factories and properties] for the complete contract. Query/Get callers must request possible-value translation when they need labels in record display values.

For TABLE sources, `overrideIdField` works for search results and direct label translation. Selected-value searches using `idList` currently still filter by the table primary key; an alternate string identifier over an integer primary key can fail conversion. This existing limitation is deferred under https://github.com/QRun-IO/qqq/issues/544[issue #544]. Use a primary-key-based possible-value source for selected-value lookup until it is resolved.
