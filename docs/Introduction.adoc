= Introduction
include::variables.adoc[]

QQQ is a metadata-driven application framework for Java engineers building business software. An application describes its tables, fields, relationships, processes, authentication and permissions in a QInstance. Backend modules perform data operations; middleware exposes the application through HTTP, CLI or other supported entry points; a separately versioned dashboard supplies the standard administration UI.

== QQQ 4.0 status and prerequisites

QQQ 4.0 requires Java 21 and Maven 3.8 or later. The 4.0 release is undergoing candidate validation; final 4.0.0 has not been published. The repository README records current availability. Existing applications should follow the xref:migration/4.0.adoc[4.0 migration guide], which covers package renames and removed APIs.

== Describe the application

Register backend connection metadata, then tables and fields that use those backends. Add relationships, possible-value sources, processes, reports and widgets as needed. Metadata can be produced by Java classes and annotations; the repository also contains metadata loaders for supported file-based definitions. Application code supplies business rules and integrations that the built-in actions do not provide.

QQQ includes relational database modules, MongoDB, filesystem storage and API backend support. Backend capabilities differ: check the selected module before relying on joins, transactions, aggregation or other optional behavior. Configure middleware and the dashboard to expose the metadata as a usable application; defining a table alone does not launch a server.

== Configure access explicitly

Choose and configure an authentication provider, such as OAuth2 or Auth0, including its required credentials and endpoints. Register it for the intended authentication scope, configure permission rules and any record-level security keys, and test permitted and denied access. Selecting a provider does not automatically define application authorization. Mock and fully anonymous authentication are useful for deliberately limited examples; the sample's explicit mock option is intended for local sample data.

== Processes and extension points

QQQ provides CRUD actions, reporting, scheduled jobs, record automations and process steps. Applications implement backend steps, customizers and widget renderers where their business behavior is needed. Streamed ETL processes separate extraction, transformation/validation and writes; preview and validation must not perform the final data changes. Production QBits, including the separate ESB QBit, have their own delivery and compatibility requirements and are outside this core release train.

== Start with the sample

Follow the {qqq-tree-url}/qqq-sample-project[sample application's README] to build and run its H2-backed tables, greeting process, dashboard and CLI. The framework build needs Docker for its integration tests. Use the metadata and action reference sections below when replacing sample behavior with your own application.
