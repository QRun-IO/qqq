=== QFieldMetaData
*QFieldMetaData Properties:*

* `name` - *String, Required* - Unique name for the field within its container (table, process, etc).
* `label` - *String* - User-facing label for the field, presented in User Interfaces.
* `type` - *enum of QFieldType, Required* - Data type for values in the field.
* `backendName` - *String* - Name of the field within its backend.
** For example, in an RDBMS-backed table, a field's `name` may be written in camel case, but its `backendName` written with underscores.
* `isRequired` - *boolean, default false* - Indicator that a value is required in this field.
* `isEditable` - *boolean, default true* - Indicator that users may edit values in this field.
* `displayFormat` - *String, default `%s`* - Java Format Specifier string, used to format values in the field for display in user interfaces.
Used to set values in the `displayValues` map within a `QRecord`.
** Recommended values for `displayFormat` come from the `DisplayFormat` interface, such as `DisplayFormat.CURRENCY`, `DisplayFormat.COMMAS`, or `DisplayFormat.DECIMAL2_COMMAS`.
* `defaultValue` - Value to use for the field if no other value is given.  Type is based on the field's `type`.
* `possibleValueSourceName` - *String* - Reference to a {link-possibleValueSource} to be used for this field.
Values in this field should correspond to ids from the referenced Possible Value Source.
* `maxLength` - *Integer* - Maximum string length in Java UTF-16 units. A supplementary Unicode character occupies two units.
Only applicable for fields with `type=STRING`.  Needs to be used with a `FieldBehavior` of type `ValueTooLongBehavior`.

==== Field Behaviors
Additional behaviors can be attached to fields through the use of the `behaviors` attribute,
which is a `Set` of 0 or more instances of implementations of the `FieldBehavior` interface.
Note that in some cases, these instances may be `enum` constants,
but other times may be regular Objects.

QQQ provides a set of common field behaviors.
Applications can also define their own field behaviors by implementing the `FieldBehavior` interface,
and attaching instances of their custom behavior classes to fields.

===== ValueTooLongBehavior
Used on String fields.  Requires the field to have a `maxLength` set.
Depending on the chosen instance of this enum, before a record is Inserted or Updated,
if the value in the field is longer than the `maxLength`, then one of the following actions can occur:

* `TRUNCATE` - Truncate to at most `maxLength` UTF-16 units, keeping surrogate pairs intact.
* `TRUNCATE_ELLIPSIS` - Reserve three units for `...` and truncate the value without splitting a surrogate pair. For a nonnegative maximum shorter than three, return only the periods that fit. The result can be shorter than `maxLength` to preserve a complete pair.
* `ERROR` - An error will be reported, and the record will not be inserted or updated.
* `PASS_THROUGH` - Nothing will happen.  This is the same as not having a `ValueTooLongBehavior` on the field.

[source,java]
.Examples of using ValueTooLongBehavior
----
   new QFieldMetaData("sku", QFieldType.STRING)
      .withMaxLength(40)
      .withBehavior(ValueTooLongBehavior.ERROR);

   new QFieldMetaData("reason", QFieldType.STRING)
      .withMaxLength(250)
      .withBehavior(ValueTooLongBehavior.TRUNCATE_ELLIPSIS);

----

===== ValueRangeBehavior
Used on Numeric fields.  Specifies min and/or max allowed values for the field.
For each of min and max, the following attributes can be set:

* `minValue` / `maxValue` - the number that is the limit.
* `minAllowEqualTo` / `maxAllowEqualTo` - boolean (default true).  Controls if < (>) or ≤ (≥).
* `minBehavior` / `maxBehavior` - enum of `ERROR` (default) or `CLIP`.
** If `ERROR`, then a value not within the range causes an error, and the value does not get stored.
** else if `CLIP`, then a value not within the range gets "clipped" to either be the min/max (if allowEqualTo),
or to the min/max plus/minus the clipAmount
* `minClipAmount` / `maxClipAmount` - Default 1.  Used when behavior is `CLIP` (only applies when
not allowEqualTo).

[source,java]
.Examples of using ValueRangeBehavior
----
    new QFieldMetaData("noOfShoes", QFieldType.INTEGER)
      .withBehavior(new ValueRangeBehavior().withMinValue(0));

    new QFieldMetaData("price", QFieldType.DECIMAL)
      .withBehavior(new ValueRangeBehavior()
         // set the min value to be >= 0, and an error if an input is < 0.
         .withMinValue(BigDecimal.ZERO)
         .withMinAllowEqualTo(true)
         .withMinBehavior(ValueRangeBehavior.Behavior.ERROR)
         // set the max value to be < 100 - but effectively, clip larger values to 99.99
         // here we use the .withMax() method that takes 4 params vs. calling 4 .withMax*() methods.
         .withMax(new BigDecimal("100.00"), false, ValueRangeBehavior.Behavior.CLIP, new BigDecimal("0.01"))
    );
----

===== DynamicDefaultValueBehavior
Used to set a dynamic default value to a field when it is being inserted or updated.
For example, instead of having a hard-coded `defaultValue` specified in the field meta-data,
and instead of having to add, for example, a pre-insert custom action.

* `CREATE_DATE` - On inserts, replaces the input value with the current `Instant` for `DATE_TIME` fields or the server's current local calendar date for `DATE` fields. Updates preserve the supplied or stored creation value.
* `MODIFY_DATE` - On inserts and updates, replaces the input value using the same `DATE_TIME`/`DATE` rules. `UpdateInput.withOmitModifyDateUpdate(true)` suppresses automatic modification-date assignment for that update.
* `USER_ID` - On inserts and updates, sets missing or blank input fields to the current user's nonblank ID. Blank follows `StringUtils.hasContent` (null, empty or trim-empty strings). An omitted field in a sparse update receives this default; an explicit nonblank value is preserved. Reads preserve stored values and never substitute the reader's ID.
* `NONE` - Disables this behavior on the field, including automatic inference for fields named `createDate` and `modifyDate`.

_Note that the `QInstanceEnricher` will, by default, add the `CREATE_DATE` and `MODIFY_DATE` `DynamicDefaultValueBehavior`
options to any fields named `"createDate"` or `"modifyDate"`.
Setting `configAddDynamicDefaultValuesToFieldsNamedCreateDateAndModifyDate=false` affects only that `QInstanceEnricher` instance. Normal validation can run another enricher with its defaults, so use an explicit `DynamicDefaultValueBehavior.NONE` on a field when the opt-out must survive validation._

[source,java]
.Examples of using DynamicDefaultValueBehavior
----
   new QFieldMetaData("createDate", QFieldType.DATE_TIME)
      .withBehavior(DynamicDefaultValueBehavior.CREATE_DATE);

   new QFieldMetaData("modifyDate", QFieldType.DATE_TIME)
      .withBehavior(DynamicDefaultValueBehavior.MODIFY_DATE);

   new QFieldMetaData("createdByUserId", QFieldType.STRING)
      .withBehavior(DynamicDefaultValueBehavior.USER_ID);
----

===== DateTimeDisplayValueBehavior
By default, in QQQ, fields of type `DATE_TIME` are stored in UTC,
and their values in a QRecord is a java `Instant` instance, which is always UTC.
However, frontends will prefer to display date-time values in the user's local Time Zone whenever possible.

Using `DateTimeDisplayValueBehavior` allows a `DATE_TIME` field to be displayed in a different Time Zone.
An example use-case for this would be displaying airplane flight times,
where you would want a flight from California to New York to display Pacific Time for its departure time,
and Eastern Time for its arrival.

An instance of `DateTimeDisplayValueBehavior` can be configured to either use a hard-coded time `ZoneId`
(for example, to always show users UTC, or a business's home-office time zone).
Or, it can be set up to get the time zone to use from another field in the table.

[source,java]
.Examples of using DateTimeDisplayValueBehavior
----
new QTableMetaData().withName("flights").withFields(List.of(
   new QFieldMetaData("departureTimeZoneId", QFieldType.STRING),
   new QFieldMetaData("arrivalTimeZoneId", QFieldType.STRING),

   new QFieldMetaData("departureTime", QFieldType.DATE_TIME)
      .withBehavior(new DateTimeDisplayValueBehavior()
         .withZoneIdFromFieldName("departureTimeZoneId")),

   new QFieldMetaData("arrivalTime", QFieldType.DATE_TIME)
      .withBehavior(new DateTimeDisplayValueBehavior()
         .withZoneIdFromFieldName("arrivalTimeZoneId")),

   new QFieldMetaData("ticketSaleStartDateTime", QFieldType.DATE_TIME)
      .withBehavior(new DateTimeDisplayValueBehavior()
         .withDefaultZoneId("UTC"))));
----

===== CaseChangeBehavior
A field can be made to always go through a toUpperCase or toLowerCase transformation, both before it is stored in a backend,
and after it is read from a backend, by adding a CaseChangeBehavior to it:

The behavior also normalizes string filter operands, including unique-key and primary-key lookups. It uses Java's default-locale case conversion. Read normalization changes the returned value without rewriting storage; caller-owned filters are preserved. Active normalization requires a string-like field (`STRING`, `TEXT`, `HTML` or `PASSWORD`). `NONE` preserves the value.

[source,java]
.Examples of using CaseChangeBehavior
----
new QTableMetaData().withName("item").withFields(List.of(

   new QFieldMetaData("sku", QFieldType.STRING)
      .withBehavior(CaseChangeBehavior.TO_UPPER_CASE),

   new QFieldMetaData("username", QFieldType.STRING)
      .withBehavior(CaseChangeBehavior.TO_LOWER_CASE)));
----

===== WhiteSpaceBehavior

Whitespace policies apply on writes, reads and string filter operands, with the same string-like field requirement. `TRIM` uses Java `String.trim`, `TRIM_LEFT` and `TRIM_RIGHT` use `stripLeading` and `stripTrailing`, and `REMOVE_ALL_WHITESPACE` removes characters for which `Character.isWhitespace` is true. These Java operations have different Unicode whitespace rules. `NONE` preserves the value. Whitespace and case behaviors can be combined on a field; read normalization does not modify stored values.

==== Field Adornments
`FieldAdornment` objects (`QFieldMetaData.withFieldAdornment(...)`) tell frontends how to present a field's value:
a `type` (an `AdornmentType`) plus a map of `values` whose keys depend on the type. They are passed through, as-is,
in v1 table meta-data (`fields.<name>.adornments`).

===== FILE_PREVIEW
A `FILE_PREVIEW` adornment renders a field as a thumbnail (for images) or a file-type icon (for other files), wherever
the frontend shows the value: query grids, record views, child-record lists and widgets. Unless `previewable` is
`false`, clicking (or pressing Enter on) the thumbnail opens a preview: the full-size image with zoom, a PDF, a video
or audio player, or a file icon with open and download links. The preview shows the file name, type, size and image
dimensions when known, and the arrow keys step through the other previewable values on the same screen.

The adorned field's own value is the default source for both the thumbnail and the full-size file. It can be a URL
(an absolute `https:` URL, or a same-origin path), or, for a `BLOB` field that also has a `FILE_DOWNLOAD` adornment,
the download URL the backend makes for it. Every value is optional. The `...Field` values name other fields of the
same table, and the frontend reads them from the same record, so they must be fields the record is queried with.

[cols="1,3"]
|===
|Value key (`AdornmentType.FilePreviewValues`) |Meaning

|`thumbnailUrlField` (`THUMBNAIL_URL_FIELD`) |Field holding a small rendition's URL, used for thumbnails. Default: the adorned field.
|`fullSizeUrlField` (`FULL_SIZE_URL_FIELD`) |Field holding the full-size (or original) URL, used in the preview and for open/download. Default: the adorned field.
|`fileNameField` (`FILE_NAME_FIELD`) |Field holding the file name. Default: the display value, else the last segment of the URL.
|`mimeTypeField` (`MIME_TYPE_FIELD`) |Field holding the MIME type, e.g. `image/png`, `application/pdf`, `video/mp4`.
|`defaultMimeType` (`DEFAULT_MIME_TYPE`) |MIME type to assume without a `mimeTypeField` value, e.g. `image/*`. Without either, the type is guessed from the file extension.
|`altTextField` (`ALT_TEXT_FIELD`) |Field holding the image's alternative text. Default: the file name.
|`captionField` (`CAPTION_FIELD`) |Field holding a caption, shown in the preview.
|`widthField`, `heightField` (`WIDTH_FIELD`, `HEIGHT_FIELD`) |Fields holding the image's pixel dimensions, shown in the preview and used to reserve the thumbnail's aspect ratio.
|`sizeBytesField` (`SIZE_BYTES_FIELD`) |Field holding the file size in bytes.
|`thumbnailMaxSize` (`THUMBNAIL_MAX_SIZE`) |Largest edge of a thumbnail in lists, in CSS pixels, from 16 to 512. Default: 40.
|`previewable` (`PREVIEWABLE`) |`false` shows the thumbnail without opening a preview. Default: `true`.
|===

`QInstanceValidator` checks that each `...Field` value names a field of the table, that `thumbnailMaxSize` is in
range, that `previewable` is a boolean and `defaultMimeType` is `type/subtype`, and that a `BLOB` field also has a
`FILE_DOWNLOAD` adornment or a `thumbnailUrlField` / `fullSizeUrlField`.

Frontends load these URLs into `<img>`, `<video>`, `<audio>` and `<iframe>` elements, so they must be allowed by the
dashboard's Content-Security-Policy. The default policy allows images from `'self'`, `data:`, `blob:` and any
`https:` origin, but media and frames only from `'self'`. A cross-origin PDF is therefore offered as open/download
links instead of an inline preview, and cross-origin video or audio falls back to those links if the policy blocks it.

[source,java]
.Thumbnails from a rendition field, and a full-size preview from the original
----
new QFieldMetaData("originalUrl", QFieldType.STRING)
   .withFieldAdornment(AdornmentType.FilePreviewValues.newFieldAdornment()
      .withValue(AdornmentType.FilePreviewValues.THUMBNAIL_URL_FIELD, "thumbnailUrl")
      .withValue(AdornmentType.FilePreviewValues.FILE_NAME_FIELD, "fileName")
      .withValue(AdornmentType.FilePreviewValues.MIME_TYPE_FIELD, "mimeType")
      .withValue(AdornmentType.FilePreviewValues.WIDTH_FIELD, "width")
      .withValue(AdornmentType.FilePreviewValues.HEIGHT_FIELD, "height")
      .withValue(AdornmentType.FilePreviewValues.SIZE_BYTES_FIELD, "fileSize")
      .withValue(AdornmentType.FilePreviewValues.CAPTION_FIELD, "caption"));
----
