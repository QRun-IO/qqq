= OAuth2 back-channel logout

Register `/qqq/v1/oidc/backchannel-logout` with the application's configured OAuth2 provider. QQQ accepts form-encoded `logout_token` notifications signed with RS256, using discovery from `baseUrl` and the issuer `externalBaseUrl` when configured (otherwise `baseUrl`). Configure `clientId` and an existing `userSessionTableName`. Tokens must contain the matching issuer/client audience, `iat`, `exp`, `jti`, the back-channel logout event, and `sub` or `sid`; `nonce` is forbidden. Issued-at age is limited to five minutes with at most 60 seconds of future clock skew. Nimbus validates signatures and registered claims. Unsupported configuration and invalid, expired or replayed tokens return HTTP 400 before privileged session access. Successful notifications return HTTP 200, including when no sessions match. See the https://openid.net/specs/openid-connect-backchannel-1_0.html[OpenID Connect specification].

QQQ removes sessions only from the configured table whose stored JWT access token has the same issuer and matches every supplied subject/session claim. Unreadable or absent stored tokens and other issuers remain untouched. Replay detection is bounded to 10,000 events within the current application process, retained for six minutes; capacity fails closed rather than evicting recent events. It is not shared across replicas or retained across restarts; expiry and signature checks still apply there. No client secrets or tokens are logged. Tests use an owned HTTP discovery/JWKS fixture and real signatures for successful logout and invalid-token/session-preservation controls.
